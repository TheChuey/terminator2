ROUND 2 — RE-EVALUATION + STABILITY FIXES (this round)
------------------------------------------------------
REVIEWED the "my tools work now" state and found the ROOT CAUSE of the original
`map_files() got an unexpected keyword argument 'args'` bug:

   The _session_aware() wrapper in factory.py used `wrapper(*args, **kwargs)`.
   Ollama builds each tool's JSON schema from the function signature, so the
   model was told the only params were "args"/"kwargs" (both strings!) and
   correctly sent {"args": [...]}. The 'defensive' *args/**kwargs tool edits
   made this WORSE - the model got zero guidance about real params.

FIXES MADE:
1. app/tools/file_map.py / file_reader.py / file_writer.py / file_delete.py
   - Reverted defensive *args/**kwargs signatures back to explicit typed params
   - Added Google-style `Args:` docstring blocks (these become the per-param
     descriptions Ollama puts in the tool schema)

2. app/agents/factory.py — _session_aware()
   - Now uses @functools.wraps(func) + __signature__/__annotations__ copy
   - IMPACT: tool schema now advertises the REAL parameters to the model

3. app/core/agent.py — new _normalize_args() runtime defense layer
   Handles the malformed shapes small models still send, in ONE place:
   - JSON-string args -> parsed
   - {"args": {...}} / {"arguments": {...}} single-key wrappers -> unwrapped
   - positional list -> bound to the tool's real params by signature
   - string booleans ("false"->False) -> coerced ONLY on params typed bool
   - stray/unknown keys (e.g. "path" on a no-arg tool) -> dropped
   Used by BOTH act() and _extract_text_tool_calls().

4. app/core/agent.py — think() no longer returns silent ""
   - Bounded tool-call loop (MAX_TOOL_ROUNDS = 6): if the model keeps issuing
     tool calls instead of a text answer, they are EXECUTED and re-prompted,
     never silently dropped. Falls back to a visible message if the model
     never produces text.

5. app/core/agent.py — FileSession context is SINGLE-SLOT
   - _inject_session_context() now REPLACES the previous "CURRENT FILE SESSION
     STATE" block instead of appending a new one every tool round (kills
     duplicate-context context bloat).

6. app/tools/file_map.py — map_files() can no longer hang the server
   - Uses os.walk (prunes ignored dirs properly), max_depth (default 8) and
     max_entries (default 5000); ignores .git/.venv/venv/node_modules/
     __pycache__/.idea/.vscode.

ROUND 3 — FIXING NARRATED (vs EXECUTED) TOOL CALLS
--------------------------------------------------
PROBLEM: In a real llama3.1:8b session, the model never actually executed the
file tools. It wrote tool-call-shaped JSON IN ITS TEXT REPLY instead of using
native tool calls, so none of the read/write/delete steps ran:

   - "read_file" with a "parameters" key    -> extraction ignored "parameters"
                                              (only arguments/args read) ->
                                              emitted call with EMPTY args ->
                                              "Missing required argument: 'path'"
   - a JSON ARRAY of 13 read_file calls     -> json.loads() succeeded on the
                                              array, but the code only accepted
                                              dicts -> 0 calls executed, the
                                              whole "read everything" step was
                                              silently dropped
   - delete_files("approved":"False")       -> empty args -> pending_deletion
                                              never registered, so the later
                                              user "yes" relied on the model
                                              fabricating paths to delete
   - the actual write step was Python code    -> extraction can't see Python,
      write_text_file('x', log, 'dir')          so nothing was written

FIXES MADE (Round 3):
1. app/core/agent.py — _extract_text_tool_calls()
   - Top-level JSON arrays of calls are now accepted (each element is a
     candidate), plus objects wrapped under "tool_calls"/"calls"/"functions".
   - The args key now accepts "parameters" in addition to "arguments"/"args".
   - Added _has_required_args() validity gate: a call is only emitted when every
     required (no-default) param is present. Narration that merely mentions a
     tool name with junk args is never executed anymore.
2. app/agents/factory.py — delete safety gate
   - delete_files(approved=True) can now ONLY delete paths that were previously
     proposed (approved=False) and recorded in session.pending_deletion.
   - Invented/fabricated paths are rejected (data["rejected"]) instead of
     deleted; if NO requested path was pending, the call is fully blocked.
3. agent_library/rag_assistant/agent.md
   - New "how to call tools" section: emit ONLY {"name","parameters"} JSON (or a
     single JSON array), never Python/pseudo-code, never fabricated paths, only
     reference paths from the session state.
