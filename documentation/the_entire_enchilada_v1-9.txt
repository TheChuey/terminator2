 1. THE BIG CHANGE (summarized)
=================================================================
A bug-fix + UX round driven by the app's real usage:

  - "SAVE TO MEMORY" ON THE REAL CHAT UI. The user chats on the
    standalone `static/chat.html` page (the window.open target), NOT the
    index.html flyout widget the V1.8 header toggle was built for. So the
    standalone page gained its own "Save to memory" checkbox in the
    header, plus the `rag` flag on both message creation and finalize:

      * new header toggle `#sc-rag` (`.sc-rag-toggle`) rendered before
        the Save button, defaulting to `settings.rag.commitOnSave`;
      * `sendChat()` now POSTs `rag`, so a chat created from chat.html
        stamps the server session flag on the FIRST message too;
      * `finalizeActiveChat()` now POSTs `{ title, rag }` to
        `/api/chats/end` on every save.

  - "SAVED CHATS DIDN'T LAND WHERE I CONFIGURED". Root cause: paths are
    resolved ONCE at import in app/paths.py, and the running server was
    started BEFORE the user saved `dataDir: "E:\\data\\rag_store"` and
    `ragDbPath: "E:\\data\\db"`. It kept writing transcripts to the old
    `chatSavePath` (`E:\saved from app`) and the store to the old
    `data\rag_db`. Two fixes:

      * `app/paths.py` now snapshots the stored path keys at import and
        exposes `restart_needed()`; `GET /api/settings` returns
        `restartNeeded: true` when the file changed since the server
        started, and the configuration UI shows an amber warning banner
        telling the user to restart the server.
      * Field notes in the config form now spell out that transcripts
        follow "Chat save path" (NOT the Data folder; blank =
        `<dataDir>\chatlog\agent-text-records`) and that path changes
        apply after a restart; a new ragDbPath starts an empty store.

  - CONFIG DATA MIGRATED (filesystem, not code). To match the user's
    configured folders:
      * `chatSavePath` was REMOVED from `static/config/app_settings.json`
        so transcripts now resolve to `<dataDir>/chatlog/agent-text-records`
        (`E:\data\rag_store\chatlog\agent-text-records`).
      * `E:\saved from app\*.txt` (5 transcripts) moved to that new folder.
      * `data\chatlog\chatRecord.jsonl` + `.active-chat.json` moved to
        `E:\data\rag_store\chatlog\` so the saved-chat dropdown survives.
      * Empty `data\chat-transcripts` and `data\chatlog` removed. The old
        RAG store `data\rag_db` is LOCKED by the running server (chroma
        file handles); it stays until the server is stopped, then the
        user deletes it. The fresh store creates at `E:\data\db` on next
        start (auto-ingest is on, so it re-indexes the moved transcripts
        on first search).

  - DOCS RE-SYNC. `documentation/_make_snapshot.py` + this v1-9 delta;
    `APP_SNAPSHOT.md` regenerated (still 52 files, 9 changelogs);
    small README note added.

 3. FILE: app/paths.py                          (CHANGED - THIS ROUND)
=================================================================
  3.1  Module docstring note added ("`restart_needed()` tells callers
       when a restart is required.").
  3.2  Right after the import-time config load, a snapshot of the path
       keys is captured:
           _PATH_KEYS = ("dataDir", "chatSavePath", "ragDbPath")
           _path_keys_at_import = {key: _get_text(_cfg.get(key))
                                   for key in _PATH_KEYS}
  3.3  New public function:
           def restart_needed() -> bool:
               """True when stored path settings changed since import -
               the running server is still using the old resolved
               locations until a restart."""
               current = _load_app_settings()
               for key in _PATH_KEYS:
                   if (_get_text(current.get(key))
                           != _path_keys_at_import.get(key)):
                       return True
               return False

        return {
