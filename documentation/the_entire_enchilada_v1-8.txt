This file chronicles ONLY the changes made to the live project since
`the_entire_enchilada_v1-7.txt` was produced. It is not a full dump of

=================================================================
 1. THE BIG CHANGE (summarized)
=================================================================
Two coupled rounds of work, both requested by the user through the app:

  - FUNCTIONAL RAG MEMORY. The prototype `rag/` module (ingest/search/
    main) is now wired into the live server as a persistent memory store
    the agents can recall with the `search_chat_logs` tool:

      * A brand-new config module, `app/paths.py`, is the single source
        of truth for every runtime folder. The UI configuration
        (`static/config/app_settings.json`) can now relocate the data
        folder, the chat-save transcripts folder, and the RAG database
        (`dataDir`, `chatSavePath`, `ragDbPath`). Absolute values are
        used verbatim; relative values resolve against the project root.
        This also fixed a real bug: the first `resolve_path()` version
        joined an absolute configured path onto the fallback, so
        `chatSavePath: "E:\\saved from app"` was silently dropped.

      * A brand-new `app/rag_commit.py` commits ONE finalized chat
        transcript into the store, and exposes purge/rebuild/status so
        the store can be forgotten or re-indexed without hand-hacking
        the chroma folder.

      * Chat sessions now carry a `rag` flag ("save to memory"). A
        per-chat toggle in the chat header controls it; the default
        comes from the new `rag.commitOnSave` setting (default false).
        On finalize, chats marked for memory are committed into the
        RAG store (never blocks the save itself).

      * `search_chat_logs` self-heals an EMPTY store exactly once per
        process by indexing every transcript - but only when the new
        `rag.autoIngest` setting is on (default true).

      * New server endpoints `GET /api/rag/status`,
        `POST /api/rag/rebuild`, `POST /api/rag/reset`, and new
        `scripts/rebuild_rag.py` CLI (`build|purge|status`).

      * A new discovered agent `agent_library/rag_assistant/` - a
        dedicated memory-recall chat agent that uses `search_chat_logs`.

  - FRONTEND CONFIG + STORE MANAGEMENT. The configuration panel gained
    Data folder / RAG database path fields, two RAG behavior toggles,
    and a live RAG-store status line with "Forget everything" /
    "Rebuild memory" buttons. The flyout chat got a configurable
    header toggle ("Save to memory") and the JS API client grew
    `ragStatus()` / `rebuildRag()` / `resetRag()`.

  - DOCS RE-SYNC. `README.md`, `documentation/CREATING_AGENTS.md`,
    `documentation/_make_snapshot.py` and `documentation/APP_SNAPSHOT.md`
    were updated to capture the new RAG architecture, and this delta
    file (v1-8) was written.

 2. NEW FILE: app/paths.py                              (ADDED)
=================================================================
Config-driven path resolution module. Adds the keys to
`static/config/app_settings.json`:

        dataDir        base data folder (default "data"); relative ->
                       project root, absolute -> used as-is
        chatSavePath   where saved chat transcripts (.txt) are written;
                       empty -> <dataDir>/chatlog/agent-text-records
        ragDbPath      where the RAG store (chroma.sqlite3) lives;
                       empty -> <dataDir>/rag_db
        rag            { commitOnSave: bool, autoIngest: bool }

Module-level resolved constants: `BASE_DIR`, `DATA_DIR`, `CHATS_DIR`,
`CHAT_SAVE_PATH`, `RECORDS_DIR`, `CHAT_RECORDS_DIR` (alias), `RAG_DB_DIR`,
`LOG_FILE`, `ACTIVE_SESSION_FILE`, `HISTORY_FILE`, `EXPORTS_DIR`,
`APP_SETTINGS_FILE`, `SERVER_SETTINGS_FILE`. Live functions:

    resolve_path(raw, *fallback_parts) -> Path   # empty raw -> BASE_DIR/parts
    _rooted(raw, default: Path) -> Path          # empty raw -> default
    rag_config(default_commit=None) -> dict      # commitOnSave + autoIngest
    about() -> dict                              # human-readable resolved paths

The `_rooted` helper is the corrected core: a present configured value is
used verbatim (`Path(text)` when absolute, `BASE_DIR / text` when
relative); nothing is re-joined onto it. `resolve_path` keeps the fallback
semantics for `dataDir`. Paths resolve at import time - restart the server
after editing path settings (rag behavior toggles read live).

 3. NEW FILE: app/rag_commit.py                        (ADDED)
=================================================================
Commit / maintain the persistent RAG store. Public API:

    commit_transcript(transcript: Path) -> str   # ingest ONE file, upsert
    purge_store() -> str                          # delete store contents
    rebuild_store() -> str                        # re-index all transcripts
    status() -> dict                              # path + chunk count + config
    _chunk_count() -> int                         # direct sqlite count

`commit_transcript` is called from `store._finalize_locked`; it ingests the
just-written transcript file (`rag.ingest.ingest_file`), upserts the
segments through `rag.search.RAGStorage(persist_dir=paths.RAG_DB_DIR)` and
is wrapped in try/except by the caller so a failed commit never blocks the
chat save. `purge_store` removes `chroma.sqlite3` /
`fallback_vector_db.json` plus leftover segment dirs. `status()` also
returns `paths.rag_config()` and `paths.about()` for the UI.

 8. FILE: rag/ingest.py                        (CHANGED - THIS ROUND)
=================================================================
New `ingest_file(file_path, chunk_size=500, overlap=50)` extracted so ONE
transcript can be indexed (per-chat commits) as well as a whole folder.
`ingest_directory` now loops `ingest_file` per `.txt`:

    for txt_file in txt_files:
        all_chunks.extend(ingest_file(txt_file, chunk_size=chunk_size, overlap=overlap))

`ingest_file` reads the file, parses header + turns, wraps each sliding
chunk with the `[title | Turn N | speaker]` context label, and returns the
`{text, raw_chunk, metadata}` dicts. No behavioral change to chunking.

 11. NEW FILE: scripts/rebuild_rag.py                 (ADDED)
=================================================================
No-arg CLI for store maintenance; the actual work is reused from
`app.rag_commit`:

    python scripts/rebuild_rag.py [build|purge|status]
      build   (default) re-index every transcript into the store
      purge   delete the store so it starts empty (transcripts kept)
      status  show store path + chunk count + current RAG behavior

Bootstraps `sys.path` with the project root, imports `app.paths` + the
commit functions, and prints the per-command summary.
