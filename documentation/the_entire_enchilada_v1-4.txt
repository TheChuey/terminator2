=================================================================
 1. THE ONE BIG CHANGE (summarized)
=================================================================
The Chat Tests feature moved OUT of the standalone chat page and INTO
the index page's Configuration section, and its runner became a full
inline runner.

Before (V1.3 / chat.html):
   - chat.html owned the whole test system: a `§15b CHAT TESTS` JS
     block with its own draft/expectation UI, a `FALLBACK_TESTS` list,
     DOM refs (testBar/testStatusText/testResults), a `createField`
     "steps" case, hooks on __scActions, and a `.sc-steps` CSS engine.
   - The index page had a `chatTests.enabled` checkbox (via the config
     form) but NO test list UI, NO way to add/delete/run anything, and
     an untracked static/js/ui/chat-tests.js module existed but was not
     wired into any page.

After (V1.4):
   1. chat.html is a chat page again. The dead test engine (CSS +
      JS + DOM) was deleted wholesale; boot() no longer calls
      initChatTests(); agents switching no longer render test steps.
   2. index.html's Configuration section now renders a full "Chat Tests"
      panel below the config form - one collapsible card PER imported
      agent (grows/contracts with the agent library), with saved-test
      lists, add/delete toggles, and Enable All / Disable All.
   3. Tests RUN INLINE on index.html against /api/chat - no page
      switch, no runTests=1 popup. Each agent-run drives one live
      server session (new_chat on the first turn, session_id reused
      afterwards), the same string/regex/type expectation engine as the
      old page, per-test verdicts, a Stop button, and a summary line.
   4. Tests kept the existing storage: settings.chatTests.tests[] in
      static/config/app_settings.json, merged by the server. Tests may
      carry agentId to scope them to one agent; global tests (no
      agentId) still run for every agent.
   5. Chat page layout got roomier (wider content column, tighter panel
      header, save-status bar moved into the composer, and the side
      panel auto-collapses on <=900px at boot so mobile gets the full
      width).

Supporting fixes along the way:
   - index.html's Configuration heading was an empty <h2> (the title was
     passed as the class name, so the heading was invisible). Fixed.
   - The forward-message picker excluded the current agent and is sorted
     by name with one-line truncation.

 2. FILE: static/js/ui/chat-tests.js            (NEW FILE - THIS ROUND)
=================================================================
NEW FILE (the untracked module that predates this round is now a real,
wired, fully-rewritten feature). Builds the "Chat Tests" section:

    import { sendChat } from "../api/api.js";

    export function renderChatTests({ mountEl, agents = [], settings = {}, onSave }) { ... }

Contract:
  - mountEl       container to append into (#chat-tests-section on index)
  - agents        [{id, name, mode, description}] from /api/agents
  - settings      the app settings object (settings.chatTests.tests is READ
                  and MUTATED in place; saved via POST /api/settings)
  - onSave        (newSettings) => void, called after every successful save

Top-level UI:
  - "Chat Tests" .config-section-heading + a .config-note intro.
  - Enable all / Disable all buttons (toolbar): flip test.enabled on
    every test, POST, then re-render all cards. On a failed save the
    previous enabled values are restored.
  - .chat-tests-cards: one card per agent (panel.agent-test-card) with a
    click-to-toggle header (name, mode badge, test count), a test list,
    a "Add a new test" step builder, and an inline runner block.

Key behaviors (net vs. the previous standalone module):
  - ADDED    agentId scoping: a test with agentId runs only for that agent;
             global tests (no agentId) run for every agent. The step
             builder stamps new tests with the card's agent.id.
  - ADDED    testsForAgent() helper - the "which tests would run here"
             filter (enabled !== false AND (global OR scoped)).
  - ADDED    inline run engine startTestRun(): loops the enabled tests for
             one agent, drives ONE server session per run:

                 const result = await sendChat({
                     message: script[index],
                     agentId: agent.id,
                     model,
                     history: run.history,
                     sessionId: run.sessionId,
                     title: test.name,
                     newChat: !run.sessionId,
                 });
                 if (!run.sessionId) {
                     run.sessionId = result.session_id || "";
                 }
                 finalReply = result.reply || "";
                 run.history.push({ role: "user", content: script[index] });
                 run.history.push({ role: "assistant", content: finalReply });

             - per-step expectations (test.expectations[i]) checked after
               each step; the first failure aborts that test with the
               offending step number.
             - a final test.expectedResult check on the last reply.
             - per-test catch => {status:"Error"} verdict, run continues.
             - Stop button sets run.cancelled; the loop breaks after the
               current step and the summary reads "Stopped after x/y".
  - ADDED    renderRun(): status line (Running... / summary with
             pass/errored colouring) + a verdict list (name/status) under
             the buttons. Run button resets to "Run tests for <name>" and
             Stop hides when finished.
  - KEPT     the same expectation engine as chat.html had:
             string (case-insensitive substring), regex (new RegExp(v,"i")),
             type: nonEmpty + number (digits kept, compared numerically).
  - KEPT     step builder: message input + "+ Add Step", draft list, Commit
             as Test (dedups by step content, stamps agentId), Clear Steps.
  - KEPT     per-test row: enabled checkbox (saves immediately), name, step
             count, delete "x" button (saves immediately, re-renders).
  - REMOVED  window.open("chat.html?agent=...&runTests=1") - replaced by
             the inline runner.

Runner state: `const runs = new Map()` keyed by agent.id so every agent
can have its own in-flight/finished run independently.

Test persistence stays: one test = {id, name, agentId?, steps[], input?,
expectedResult?, enabled?}; saveTests() POSTs {chatTests:{enabled,tests}}
to /api/settings and calls onSave(data.settings) so config.js can refresh
its cached settings. (server.py merges, so unrelated settings survive.)

    @app.delete("/api/chats/{chat_id}")
    async def delete_chat(chat_id: str):
        """Permanently erase a chat: its .txt transcript(s) + log records (+ the
        active session when that is the chat being deleted)."""
        result = chat_store.delete_chat(chat_id)
        if not result["recordsRemoved"] and not result["filesRemoved"] and not result["wasActive"]:
            raise HTTPException(status_code=404, detail=f"Chat '{chat_id}' not found")
        return {"deleted": True, "id": chat_id, **result}

 8. FILE: app/chat_store/store.py             (CHANGED - STARTED ROUND)
=================================================================
STARTED ROUND (uncommitted vs. v1-3). Added the backing function for the
DELETE endpoint (added to __all__ as well). It defends against the
import-on-boot re-scan: transcripts must be unlinked, not just de-logged.

    def delete_chat(chat_id: str) -> dict:
        """Erase a chat completely: its log records, EVERY versioned .txt transcript,
        and the live active session when it is the one being deleted.

        The records alone are not enough - import_once() rescans the transcript
        folder on boot, so the .txt files must be unlinked too or the chat would
        come back. Returns a summary dict, or an all-zero dict when the id is
        unknown (callers decide whether that is an error).
        """
        with _lock:
            records = _metadata_logger.list_all()
            mine = [record for record in records if record.get("id") == chat_id]

            files_removed = []
            for record in mine:
                file_name = record.get("fileName", "")
                if not file_name:
                    continue
                path = _resolve_transcript(file_name)
                try:
                    if path.exists():
                        path.unlink()
                        files_removed.append(file_name)
                except OSError:
                    continue

            records_removed = _metadata_logger.remove(chat_id)

            was_active = False
            active = _load_json(ACTIVE_SESSION_FILE, None)
            if active and active.get("id") == chat_id:
                was_active = True
                try:
                    ACTIVE_SESSION_FILE.unlink()
                except OSError:
                    pass

            if records_removed or files_removed or was_active:
                print(
                    f"[CHATS] deleted '{chat_id}' "
                    f"({len(files_removed)} file(s), {records_removed} record(s), active={was_active})"
                )
            return {
                "recordsRemoved": records_removed,
                "filesRemoved": files_removed,
                "wasActive": was_active,
            }

No other store.py behavior changed this round.
