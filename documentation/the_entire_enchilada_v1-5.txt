 1. THE ONE BIG CHANGE (summarized)
=================================================================
Two user-driven features landed this round:

  A. THE TESTS CAN NOW RUN INSIDE CHAT.HTML. In V1.4 the saved chat
     tests could only be run as a VERDICT LIST on the index page. The
     user asked for a way to INJECT a saved test into chat.html so the
     actual assistant output can be seen in the real chat UI. Resolution:
     - The Configuration page's per-agent card got a "Run tests in chat
       ->" button that opens
           chat.html?agent=<id>&runTests=1
     - chat.html gained a saved-test RUN MODE (a new JS section). It
       plays every ENABLED test for that agent as real chat messages,
       driven through the existing sendTurn() pipeline (so bubbles,
       session tracking, transcripts and save all work), with a pinned
       status banner + Stop button and a verdict summary at the end.
     - Additionally, the appearance of chat.html now mirrors the index
       page's typography settings (see feature B below).

  B. AN APPEARANCE SETTINGS SECTION. A new "Appearance" section on the
     Configuration page with ONE global font family + base font size,
     applied to BOTH the index page and chat.html. Both pages read the
     stored appearance settings on load and apply them through CSS
     variables, and the primary text sizes were converted to rem so the
     size knob visibly scales the whole UI. The section has a live
     preview and a Save button that persists via the merging
     POST /api/settings.

 3. FILE: static/chat.html                    (HEAVILY CHANGED)

This round added feature A's run mode and feature B's typography.

3.1  NEW "18b. SAVED-TEST RUN MODE" JS section
     (between application boot and section 19 event wiring).

  State + Stop:
     let testRunActive = false;
     let testRunCancelled = false;

     function stopTestRun() {
         testRunCancelled = true;
         const btn = DOM.messages.querySelector(".sc-test-run-stop");
         if (btn) btn.disabled = true;
         setSaveStatus("Stopping after the current step...", "");
     }

  Boot wiring (inside boot()): when ?runTests=1, the auto-hi prefill and
  the ?prefill= handling are skipped and the runner starts instead:

     if (params.get("runTests") === "1") {
         startTestRunInChat();
     } else {
         maybeAutoHi();
     }

     const prefillText = params.get("prefill");
     if (params.get("runTests") !== "1" && prefillText && prefillText.trim()) { ... }

  Test selection - same rules as the index runner:
     const mine = allTests.filter(test =>
         (test.enabled !== false) &&
         (!test.agentId || test.agentId === activeAgent.id)
     );

  Re-added (they were deleted with the old test engine in V1.4):
     testScript(test)     - steps[] or the legacy input-string splitter
     checkExpectation()   - string (substring, case-insensitive), regex
                            (new RegExp(v, "i")), type: nonEmpty | number

  The play loop drives the REAL send pipeline (sendTurn, the same one
  the composer uses) so every step is a real visible bubble, one server
  session per run (the first step creates it, later steps reuse it):

     finalReply = await sendTurn(script[index]);
     setWaiting(false);

  A pinned banner is appended into the thread:
     DOM.messages.appendChild(banner);  // .sc-test-run-banner w/ Stop btn
     setBanner("Running tests for " + activeAgent.name + "...", 0);

  Per-step expectations abort that test with the offending step number;
  a per-test try/catch marks it Error and the run continues; Stop breaks
  after the current step. After the loop the banner is removed and a
  summary system bubble is appended:

     Saved-test run for <agent>: N/M passed.
     [PASS]  test name
     [FAILED]  test name - Expected "x" in reply. (step 2)
     ...

  setSaveStatus() shows the summary (ok = all passed). Composer input is
  protected from mid-run typing: handleSend() early-returns while
  testRunActive.

 4. FILE: static/js/ui/appearance.js            (NEW FILE - THIS ROUND)
=================================================================
NEW FILE. The Appearance settings section module:

    import { saveAppSettings } from "../api/api.js";

    FONT_OPTIONS = [
        { value: "", label: "System default" },
        { value: "Arial, Helvetica, sans-serif", label: "Arial / Helvetica" },
        { value: "'Segoe UI', Tahoma, sans-serif", label: "Segoe UI" },
        { value: "Verdana, Geneva, sans-serif", label: "Verdana" },
        { value: "Georgia, 'Times New Roman', serif", label: "Georgia (serif)" },
        { value: "'Courier New', monospace", label: "Courier New (mono)" },
    ];

    SIZE_OPTIONS = [13, 14, 15, 16, 17, 18];   // px

    export function applyAppearance(appearance) { ... }   // sets/removes
                                                          // --app-font-*
    export function renderAppearance({ mountEl, settings, onSave }) { ... }

renderAppearance() builds:
  - ".config-section-heading" "Appearance" title + a .config-note intro
    stating the setting applies to BOTH pages.
  - A .panel with two .field <select>s (#appearance-font-family,
    #appearance-font-size) pre-filled from settings.appearance (missing
    values default to family "" and size 16).
  - A .appearance-preview strip that live-refreshes its font-family and
    font-size on every select change.
  - "Save appearance" (btn-primary) below, which POSTs
    { appearance: { fontFamily, fontSize } } through saveAppSettings(),
    applies the result to the current page via applyAppearance(), and
    calls the onSave callback. Failure shows the error message.
